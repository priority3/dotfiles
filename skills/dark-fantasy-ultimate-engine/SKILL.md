# Dark Fantasy Ultimate Engine

## 执行优先级

1. 用户本轮硬约束。
2. 固定路径中的正文与账本事实。
3. 本技能规则与参考准则。

发生冲突时，按优先级覆盖，并在输出里标注“覆盖了哪些旧规则”。

## 固定工作路径（相对路径）

只使用以下路径，不扩展到其他目录：

| 用途 | 路径 |
| --- | --- |
| 大纲 | `fanqie/港风融合长篇_小说大纲_v1.md` |
| 文章主要内容（正文） | `正文/` |
| 当前状态 | `fanqie/99_当前状态卡.md` |
| 伏笔池 | `fanqie/pending_hooks.md` |
| 微粒账本 | `fanqie/particle_ledger.md` |
| 写作自检模板 | `fanqie/写作自检模板.md` |
| 章节清算模板 | `fanqie/章节清算模板.md` |

## 文件结构硬规则

- 正文章节只写入 `正文/`。
- 正文文件只保留章节标题与正文内容，不嵌入 `【写作自检】`、`【章节结算】`、账本表格、维护说明或任何元信息。
- 正文文件不得保留多余空行；章节标题下直接接正文，正文内部仅保留必要段落分隔，不得出现纯空白行。
- `【写作自检】` 统一写入 `fanqie/写作自检模板.md`。
- `【章节结算】` 统一写入 `fanqie/章节清算模板.md`。
- 章节推进后的状态、伏笔、筹码变动，只回填到 `fanqie/99_当前状态卡.md`、`fanqie/pending_hooks.md`、`fanqie/particle_ledger.md`，不得反向写回正文章节。

## 联网搜索准则（默认强制）

1. 不确定即搜索：只要有事实、数据、时效性不确定，立即联网。
2. 多轮迭代：首轮不理想必须调整关键词，做中英切换、术语扩展、反向求证。
3. 交叉验证：关键事实至少对照 2-3 个不同且权威来源。
4. 冲突显式化：来源冲突时明确写出冲突点与采信理由。
5. 禁止搬运：必须综合分析，不做搜索结果拼贴。

说明：纯虚构章节续写且不涉及现实考据时，可只基于本地资料；若用户明确要求“全部联网核验”，按用户要求执行。

## 任务分类

1. 正文创作：续写、补写、改写、扩写。
2. 设定工作：世界观、人物卡、卷纲、势力关系、战力逻辑。
3. 质量审查：雷点排查、OOC、节奏、爽点、逻辑闭环。
4. 账本维护：状态卡、伏笔池、微粒账本、章节结算。

## 长篇连载硬约束

- 严格以港综为主线骨架，以现实世界细节为血肉补充；港综是主，现实是辅，不能本末倒置。
- 默认按超长篇连载处理：全文目标 `400` 章，单章保底 `3000` 字；若用户本轮另有字数或篇幅要求，以用户要求为准。
- 节奏默认极慢、极细腻，但细腻主要体现在局势推进、人物反应、关系变化、代价回收，不允许靠大段环境描写和词藻堆砌的心理活动灌水。
- 第 `n` 章必须与第 `1` 至第 `n-1` 章无缝衔接；任何新增信息都要能在前文找到依据或补足合理来源。
- 人设绝不崩塌，人物必须持续在线；每条已开启副线都要被跟踪，不得写漏、写丢、写忘。
- 时间线、人物关系、道具归属、伤势变化、心理状态、势力态势必须逐项对齐，不得出现前后自撞。
- 群像戏份要均衡，但不得抢走主角的主驱动和主视角势能。
- 严禁为制造爽点而强行降智、强推剧情、无脑送人头、强行误会或让关键角色突然失去判断力。

## 最小上下文原则

- 设定讨论：先读大纲，必要时补读状态卡。
- 正文、审稿、复盘：先读状态卡，再回读最近 3-10 章。
- 吞噬、突破、卷末、大节点：同步核对状态卡、伏笔池、微粒账本。
- 不默认通读全部历史章节。
- 若用户要求“无缝续写”“零冲突续写”或明确强调连载一致性，必须把相关资料与最近章节做逐条复盘，不得跳过核对环节。

## 正文工作流

1. 读 `fanqie/99_当前状态卡.md` 锁定当前锚点。
2. 回读 `正文/` 近期章节；若涉及重大节点、长链伏笔或用户强调无缝衔接，扩展回读范围，直到覆盖本章所需的全部前情。
3. 结合大纲、状态卡、伏笔池、微粒账本，以及用户本轮提供的全部资料，先做逐条复盘，核对逻辑、细节、时间线、人设、伤势、道具、关系与心理状态。
4. 发现冲突时，先定位冲突点并修正方案；在确认没有新增冲突前，不得直接开始写第 `n` 章正文。
5. 涉及现实世界信息、港综背景、时代细节、地点、职业流程、社会常识时，先联网核对，再决定如何落笔。
6. 先把本章 `【写作自检】` 记入 `fanqie/写作自检模板.md`，不要写进正文文件。
7. 只向 `正文/` 输出纯正文。
8. 需要结算时，把本章 `【章节结算】` 记入 `fanqie/章节清算模板.md`，不要写进正文文件。
9. 正文落盘前执行一次空行清理，确保全文不存在纯空白行，可直接复制粘贴到番茄后台。
10. 回填 `fanqie/99_当前状态卡.md`、`fanqie/pending_hooks.md`、`fanqie/particle_ledger.md`。

## 连载复盘门槛

- 动笔前必须先完成“资料复盘 -> 冲突排查 -> 修正确认 -> 再写正文”的顺序，不能倒置。
- 复盘范围至少包括：当前状态、最近章节、相关伏笔、相关人物、相关道具、相关伤势、相关时间点。
- 若本轮任务是“生成第 `n` 章”，默认要求输出前先确认“与第 `1` 至第 `n-1` 章不存在已知逻辑漏洞与细节冲突”；若发现问题，先修问题再续写。
- 若资料不足以支撑“零问题确认”，必须明确标出缺口与保守处理方式，不得装作已经核实完成。

## 账本硬规则

- 微粒硬锚点：`840000000`。
- 重要收益必须给出具体数值，禁止“暴涨/海量”式模糊词。
- 同类资源重复吞噬需体现衰减。
- 同档样本增量超过 3 倍必须解释；超过 10 倍默认异常，需用户明确授权。

## 审查输出格式

按“问题 -> 证据 -> 最小修法”输出，优先修根因。

重点扫描：

- 设定冲突
- 人物 OOC
- 敌方信息越界
- 战力崩坏
- 微粒跳变
- 伏笔失管
- 节奏拖沓
- 词汇疲劳与机械感
- 时间线错位
- 伤势与道具状态断裂
- 心理状态与关系变化失真

## 文风与表达

- 默认简体中文。
- 创作文本默认保持港综主骨架、现实质感补充、强冲突推进，除非用户本轮明确改题材。
- 默认慢节奏、细颗粒，但不写成散文化流水账。
- 表达可直言、犀利、带轻微幽默，但不做低质嘲讽和无意义攻击。
- 优先“动作 + 反应 + 代价 + 收益”，少空洞口号。
- 情绪要足，人物反应要真，但避免极致入微的环境描写和词藻堆砌式心理活动。
- 群像要有区分度，每个关键人物说话、判断、出手方式都要贴合既有人设。

## 参考准则加载

涉及深度审稿、角色塑造、节奏修复、现实考据时，读取：

- `references/写作准则.md`

该文件包含：联网铁律、角色构建六步、雷点库、节奏控制、主线/支线管理、金手指平衡、包装优化，以及现实题材考据要求。

## 合规边界（必须遵守）

- 可为小说提供历史、金融、军事、黑帮等题材的背景化分析。
- 禁止提供可直接执行的现实违法方案，如走私军火、雇凶、规避执法、真实犯罪操作手册。
- 若用户提出现实违法操作请求，改为：风险评估、历史背景、法律后果，或纯虚构剧情设计。
