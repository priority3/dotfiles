# 接缝：静态对了之后，检查动态

"反模式清单"管的是**静态**——一个东西单独看长什么样。
但真正让人觉得"像拼起来的"的，是**接缝**：两个东西交接的那一瞬没接好。

这种感觉通常只能是"说不出来，但怪怪的"。它之所以难改，是因为没被拆开。拆开之后只有五种：

| 缝 | 没接好的样子 | 怎么检查 |
| --- | --- | --- |
| **时间** | 东西突然出现、突然消失；亮度"啪"一下断掉，像断电 | 录屏逐格看出现/消失那几帧 |
| **顺序** | 该先发生的事晚了一步 | 把动作按时间写成一行一行，看有没有倒序 |
| **空间** | 跟旁边原本就在的东西对不上（层级、对齐、z 序） | 跟背景、隔壁元素叠在一起看 |
| **道理** | 用了不属于它的规则 | 问：**这条规则是谁的？** |
| **笔触** | 质感跟全站不是同一支笔 | 跟全站最典型的元件并排看 |

再加一个通用问题，比上面五个都灵：

> **它的下一步是什么？**

一个东西如果只有"现在"，没有前因后果，看久了就会假。机械臂把箱子拿起来了——那箱子之后去哪了？

## 逐条落到 pr-agent

这些不是假设，是读代码时能指出行号的真问题。

**时间缝 · 勾选圈在弹，文字 instantaneous 变色**
`.pr-tick` 的 `transform` 是 `.25s var(--pr-spring)`，而条目文字的 `color` 没有 transition，勾上的一瞬间字直接变灰、圈还在弹。
读者感到的是"字先死、圈后才到"。→ 给文字 `transition: color .18s`，或者让圈的 `background` 也走 `.18s`，两者取同一个值。

**顺序缝 · 流式结束 → 元信息行**
回复最后一个 token 落地，同时"已思考 N 秒"和复制按钮一起出现。真实的顺序是：先写完，再结算。→ 元信息行延迟 120–200ms 淡入，不要和正文抢同一帧。

**空间缝 · 勾选计数与条目距离**
计数行 `margin-top: 8px`，而条目之间是 1px 线 + 11px padding。计数行看起来"贴"在最后一条上，因为它不吃同一条分隔规则。→ 要么给它一条 1px 线，要么把它并进最后一条的 padding 里。

**道理缝 · AI 回复裸文本，用户消息却有卡片底**
表面上违反"内容前置"。检查"这条规则是谁的"：卡片底的作用是区分**输入**和**内容**，不是装饰容器。规则没被违反，但它是**有理由的例外**——例外必须写下来，否则下一个人会以为是漏掉了。

**笔触缝 · 圆角梯子有四档**
卡片 10 / 用户消息 12 / 输入区 14 / 控件 8。四档太密，读者分不出"12 和 14 有区别"，只会觉得"有点不齐"。→ 收敛到三档：控件 8 / 卡片 12 / 输入区 14，或干脆两档。

**下一步缝 · 勾完全部之后没有收束**
3 条全部勾完，底部还是"3 条建议 · 已勾 3 条"。没有"做完了"，也没有"然后呢"。
这是**产品缺口**，不只是视觉缺口：条目全部完成时应该有一句收束（以及一个自然的下一步，比如记一条训练备注）。
按"它的下一步是什么"问一遍，这类缺口会成片地冒出来——它们几乎都不可能靠调像素解决。

## 用在哪里

不要把它当设计评审表用（太晚）。**用在提交之前**，对本次改动的每一个新交互问一遍五道缝 + "下一步"。
一个界面里没接好的地方一多，就会开始像拼起来的；反过来，一个一个接好之后，用户就算说不出为什么，也会觉得它是一个完整的地方。

## 说不出哪里不对的时候

三件事，按顺序：

1. **找真实的东西对照。** 不是找"好看的界面"，是找真实的参照物（真实的手表数据长什么样、真实的配速分布是什么形状）。
2. **看别人怎么做。** 只看它**为什么**这么做，不看它做了什么。
3. **把规格查清楚。** 很多"怪"其实是事实没搞懂——对比度、色差、字号档位都是可以量的。
