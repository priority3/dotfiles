# 世界观：答不出来的东西，就不该在

pr-ui 的三条硬规矩管的是"长什么样"。但在那之前还有一个更前置的问题：**这东西凭什么在这里？**

判据不是"好看不好看"，也不是"真不真实"，而是**和和谐不和谐**。而和谐可以拆——拆成一张问题表。

## 用一张表把世界观问出来

每个界面都会遇到同一批问题。把这些问题列出来，用你的产品一题一题回答。**答得出来的，是这个世界的居民；答不出来的，放上去就是"贴上去的"。**

| 每个界面都会遇到的问题 | 你要回答的 |
| --- | --- |
| 读者从哪进来？第一眼看到什么 | |
| 他正在做什么事？被打断了会怎样 | |
| 状态变化怎么表达（出现/消失/成功/失败） | |
| 等的时候是什么样 | |
| 什么都没有的时候说什么 | |
| 出错了怎么说话 | |
| **什么不能出现** | |

最后一行跟前六行一样重要。世界不只告诉你能做什么，也告诉你不能做什么——**这是减法的第一步，也是最容易被跳过的一步。**

举一个真实的例子：有人做海王星主题，有一版把转场里飞行的尾巴画成一道道风线。风是行星大气里的东西，而换页发生在星星之间。整个拿掉。
不是"不好看"，是**在这个世界里说不通**。

## 示范：pr-agent 的世界观

产品是给运动者的对话式助手（PR ·「你的运动伙伴」），记得训练史，会给具体动作建议。

| 问题 | 回答 | 落到界面上 |
| --- | --- | --- |
| 第一眼 | 一次对话的中段，刚跑完或马上要跑 | 直接是消息流，没有首页、没有仪表盘 |
| 正在做什么 | 读一段建议，然后决定做不做 | 建议必须是可操作的条目，不是散文 |
| 状态变化 | 像人在说话，不像机器在响应 | 无气泡、无"正在生成"字样、无 spinner 文案 |
| 等的时候 | 想事情 | 思考过程可展开，秒数等宽 |
| 什么都没有 | 「还没有记录，跑一次就有了」 | 空态给下一步，不给插画 |
| 出错 | 直说哪一步断了、怎么补 | 不甩错误码，不说"系统繁忙" |
| **什么不能出现** | 排行榜、连续打卡天数、勋章、等级、进度环百分比、emoji 装饰、「AI 正在生成」 | 这些是**游戏化和工程**的语言，属于另一个世界 |

那张负面清单解释了一件本来想不通的事：为什么"把建议变成可勾选条目"读起来就是对的，而"加个连续打卡"读起来就不对。
**第一条是教练在给动作，第二条是应用在要留存。** 世界观在这里直接替你做完了产品决策。

## 世界观不限制想象力，只限制无理由

定了"教练"不等于只能写训练术语。可以有人名、可以有玩笑、可以引用他三个月前的比赛。条件是：**每一样都说得出为什么在这里。**

同样，参考别人的界面时——**只取规则，不取像素。**
从 ryugi 那一页我们拿的是"描边 + 极淡双层影"这条公式，不是它的便签、点阵画布和跳格子的小人。那些是它的世界的居民，搬过来就是"贴上去的"。

## 怎么用

1. 新项目开工，先把这张表填完（15 分钟，能省掉后面所有"这里该放什么"的争论）。
2. 每次要加一个新元素，先问：**它在那张表里是哪一行？** 答不出来就不加。
3. 改版时先重填"什么不能出现"，它比"要加什么"更能定住方向。
