# 可勾选条目模式

把「要用户做的决定」从散文里拎出来，变成能点、能记、能回看的控件。
这是 pr-ui 里唯一改产品而不只是改外观的一条，也是收益最大的一条。

## 什么时候该拆

| 信号 | 处理 |
| --- | --- |
| 正文里出现「接下来三天可以这样：A；B；C」 | 拆成条目 |
| 出现「第一、第二、第三」但每点都是一个动作 | 拆成条目 |
| 连续的短句，每句都能独立执行/验证 | 拆成条目 |
| 只是解释原因、描述状态 | **不拆**，保持散文 |

判据一句话：**一行文字如果可以被"做过/没做过"判定，它就是条目；否则是正文。**

## 数据契约（零后端改动版）

最省事、最可控的一版：**让模型直接输出 GFM task list**，前端解析。

```markdown
先别急着停，也别硬撑。膝外侧疼在跑量突然上来时很常见。

- [ ] 今天剩下的跑量换成快走
- [x] 泡沫轴滚髂胫束，每侧 2 分钟
- [ ] 跑前加一组臀中肌激活
```

好处：模型不用学新格式（它本来就会写 task list）、历史消息天然兼容、不引入 JSON schema、流式渲染能逐条出现。

**前提**：prompt 里必须允许它分点。如果原 prompt 写着"别分点罗列"，清单永远等不到——这是最容易漏的一步。
改法（一行内替换，不新增段落）：

```diff
- 别写小作文，别分点罗列（除非他明确要清单）。
+ 别写小作文，别用「第一、第二」分点；真要给他几个具体动作时，用 `- [ ]` 一行一条（2~4 条，每条一句话），别摊成一段话。
```

## 解析规则

```ts
const ITEM_RE = /^\s*[-*+]\s+\[([ xX])\]\s*(.*)$/
```

要点：

1. **只切连续命中行，其余仍走原 markdown 渲染器。** 不要为清单另写一套渲染器，否则代码块、表格、数学公式全要重做一遍。
2. **代码围栏内不解析**（``` / ~~~ 之间）。否则一段示例代码会被拆成可点条目。
3. **流式时末尾可能是空条目**（`- [ ] ` 刚打出符号还没打内容）——先占位，不渲染。
4. **单条不渲染成清单。** 一个孤零零的勾选框读起来像"格式错了"。

⚠️ 第 4 条的正确实现是**退化回 md 段**，不是把整段过滤掉：

```ts
// 错:直接 filter 掉了,那一条的文字跟着消失(内容丢失)
return out.filter(seg => seg.kind !== 'list' || seg.items.length > 1)

// 对:不足两条时退回 md
return out.map(seg =>
  seg.kind === 'list' && seg.items.length <= 1
    ? { kind: 'md', text: seg.items.map(i => `- [${i.done ? 'x' : ' '}] ${i.text}`).join('\n') }
    : seg
)
```

## 勾选状态存哪

**挂条目文本的哈希，不挂消息 id。**

```ts
function hash(text: string): string {
  let h = 5381
  for (let i = 0; i < text.length; i += 1) h = ((h * 33) ^ text.charCodeAt(i)) >>> 0
  return h.toString(36)
}
```

原因：消息 id 在一条消息的生命周期里会变**两次**——本地 `newId()` 生成 → 服务端落库返回 → 历史重拉又是新的。挂 id 上的勾选会在刷新后凭空消失，用户会直接不信这个功能。
挂文本上则同一条建议（哪怕换了会话、换了设备同步过来）依然记得勾过。

存储：`localStorage` 一个对象即可，够用且不涉及后端。

```ts
const STORE_KEY = 'pr_checks'   // { [hash]: true }
```

- 读写都包 `try/catch`：隐私模式写入会抛异常，勾选丢失不影响阅读，静默降级。
- 只存 `true`，取消勾选就 `delete`，别存 `false` 让数据无限膨胀。

## 视觉规格

| 元素 | 值 |
| --- | --- |
| 条目纵向内边距 | 11px（触控目标高度 ≥ 38px） |
| 勾选圈 | 15×15，`border: 1px solid --pr-line-strong`，圆角 `9999px` |
| 勾选后 | 底 `--pr-accent`，勾用 `--pr-accent-ink`，`scale(1.06)` |
| 条目文字 | 13.5px / 1.6；勾选后转 `--pr-muted` |
| 条目间分隔 | `1px solid --pr-line`，不加圆角、不加底色 |
| 底部计数 | 11px，`--pr-muted`，「3 条建议 · 已勾 1 条」 |
| 空态提示 | 「点一下算做过」——比"0/3"更像人话 |

**整块不要加卡片底色和圆角**。它属于正文，只在顶部加一条 1px 线分隔即可。
一旦给它套上卡片，"建议"就变成了"模板"。

## 交互

- `<button type="button" aria-pressed>`，不要用 div + onClick。
- `:active` 给 `background: --pr-sel`，让手指有落点反馈。
- 勾选圈 `scale(1.06)` 配合 `cubic-bezier(.34,1.56,.64,1)`，是一个很小的"确认"。
- **不要**弹 toast、不要撒花。勾选是低风险动作，反馈越轻越好。

## 踩过的坑

| 坑 | 现象 | 解法 |
| --- | --- | --- |
| 文件名 `checklist.ts` + `Checklist.tsx` | macOS 大小写不敏感盘上撞成 `TS1261: already included file name` | 解析模块改名 `tasklist.ts` |
| 勾选挂消息 id | 刷新后勾选消失 | 挂文本哈希 |
| 单条清单被过滤掉 | 那一条的文字一起消失 | 退化回 md 段 |
| 代码块里的 `- [ ]` | 示例代码被拆成可点条目 | 围栏内跳过 |
| prompt 禁止分点 | 清单永远等不到 | 改 prompt，一行内替换 |
