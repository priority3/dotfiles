# 设计令牌

## A. ryugi.innei.dev 画布页实测值

出处：`npx ryugi-artifacts get "https://ryugi.innei.dev/a/f9X6xjti9ibMFzJ3p037m"` → `pages/cursor/roster.html`。
全部为 CSS 原文摘抄，不是估算。

**画布**
```css
background: #f4f4f5 radial-gradient(#d4d4d8 1px, transparent 1px) 0 0 / 16px 16px;
```
点阵 16px 一格、1px 点、比底色深两档。作用不是装饰，是给"可以摊开的桌面"一个触感基准。

**板（board）**
```css
background: #fff;
border-radius: 2px 6px 6px 6px;                       /* 左上角留尖:气泡指向 */
box-shadow: 0 2px 5px rgba(0, 0, 0, .14);             /* 常态 */
box-shadow: 0 0 0 1px #d4d4d8, 0 2px 5px rgba(0, 0, 0, .14);  /* 选中/强调 */
```

**字号**：只有 11px、12px、12.5px、13px 四档；标签 11px / 600。数字 `font-variant-numeric: tabular-nums`。

**顶栏**：44px 高。整页只有一条栏，没有侧边栏、没有标签页、没有二级工具条。

**仅有的彩色**：便签的暖黄。其余 21 个 agent 的品牌色属于"内容"（logo），不属于装饰——
这是全篇最重要的分界线：**装饰用色 = 花，内容用色 = 专业。**


## C. 用色算法：品牌色配什么字

手工挑 20 组前景/背景必然翻车。让代码挑：

```ts
// WCAG 相对亮度
function luminance(hex: string): number {
  const [r, g, b] = [1, 3, 5].map(i => {
    const c = parseInt(hex.slice(i, i + 2), 16) / 255
    return c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4
  })
  return 0.2126 * r + 0.7152 * g + 0.0722 * b
}

const ink    = luminance(brand) > 0.4 ? '#000' : '#fff'          // 字色
const border = luminance(brand) > 0.8 ? 'rgba(0,0,0,.12)' : 'rgba(255,255,255,.24)'  // 描边
```

阈值 0.4 / 0.8 是实测出来的分界：低于 0.4 用黑字会糊，高于 0.8（近白底）用白描边看不见。
放一排黑白混杂的 logo 也不花，靠的就是这个。

## D. 颜色：先定角色，再挑颜色

大部分人配色是"先挑几个喜欢的颜色，再想放哪"。反过来才对：

**先决定需要哪几个角色，每个角色只有一个意思，最后才填颜色。**

| 角色 | 干什么 | 数量约束 |
| --- | --- | --- |
| 纸 | 所有东西画在这上面 | 1 个 |
| 墨 | 字、线、图标 | **1 种颜色**，用透明度分层 |
| 讯号 | 只代表"你在这里"或"这个状态成立" | 1 个，全站唯一有颜色的东西 |
| 警示 | 只在出错时出现 | 1 个，必须和讯号色差得够远 |

两个铁律：

- **纸不用纯白/纯黑。** 纯白在深色底上刺眼；纯黑在浅色底上发死。各带一点点色温，长文读久了眼睛不累。
- **墨只有一个颜色，层级靠透明度。** 标题、正文、说明、线全是同一个墨的不同 alpha。这样层级天然单调——不会出现"某个灰比另一个灰更深但位置更次要"的错乱。

### 每一层都要量，不能拍脑袋

墨 `#111114` 在 `#ffffff` 上、墨 `#f2f2f4` 在 `#0b0b0d` 上，逐档实测（WCAG 对比度）：

| alpha | 亮色合成色 | 对比度 | 暗色合成色 | 对比度 | 能用来做什么 |
| --- | --- | --- | --- | --- | --- |
| 100% | `#111114` | 18.85:1 | `#f2f2f4` | 17.59:1 | 正文 |
| 84% | `#37373a` | 11.86:1 | `#cdcdcf` | 12.39:1 | 标题、强调 |
| 72% | `#545456` | 7.56:1 | `#b1b1b3` | 9.19:1 | 次级文字、标签 |
| 60% | `#707072` | **4.94:1** | `#969698` | 6.66:1 | **小字的下限**（11px 也只能到这里） |
| 48% | `#8d8d8e` | 3.32:1 ❌ | `#7a7a7c` | 4.59:1 | 亮色只能做图标/大字 |
| 15% | `#dbdbdc` | 1.40:1 | `#2e2e30` | 1.55:1 | 分隔线、描边 |

**关键结论：11px 的文字在亮色底上，alpha 低于 60% 就不合格。** 小字本来就需要更多对比度补偿，浅灰 + 小字是双重惩罚。

对照一下现状：pr-agent 用的 `--pr-muted: #a3a3ac`（≈ 39% 墨）在白色底上是 **2.50:1**，在 `#f4f4f5` 卡片上是 **2.28:1** —— 它承载的正是"已思考 4 秒""3 条建议 · 已勾 1 条"这些 11px 元信息，**实际读不清**。修法是提到 60% 墨（`#707072`），色相没变、只是沉下去一档。

同样值得量一遍的还有勾选圈：`--pr-accent-ink #1a2e05` 在 `#a3e635` 上是 9.69:1，那个 9px 的勾没问题。

## E. 黑白测试

最后一个检查最简单，也最有用：**把颜色全部降成灰，东西还认得出来吗？**

如果两个状态只能靠颜色区分，说明**形状没做好**。绿色不该是"已勾选"的唯一信号。

pr-agent 的勾选条目是四重信号，所以它在灰度下依然成立：

| 信号 | 灰色下还在吗 |
| --- | --- |
| 圆圈从空心变实心 | ✅ 形状 |
| 圈里出现勾 | ✅ 形状 |
| 文字转淡 | ✅ 亮度 |
| 圈是绿色 | ❌ 但只是第四重，不承担表意 |

反过来，如果只有最后一重，那就是"靠颜色撑着的设计"，换个色盲用户、换个打印、换个灰度截图就崩了。

## F. 给预设，不给旋钮

如果这套 token 要给别的项目用（`templates/pr-ui.css` 就是），最后一个决定是：**开放多少。**

结论是**不开放自由调色**。能选的只有做好的几套预设（亮/暗 × 若干强调色），能填的只有内容。

原因和 D 节一样：讯号色必须和纸、墨都分得开，而且跨主题之间也要分得开（实测判据是色差 ΔE2000 ≥ 20，否则两颗"你在这里"会被认成同一个）。
开放任意色码等于让人随手拆掉其中一块，而他没有工具去量。

这和"减法"是同一条原则，只是拿掉的是旋钮。
