# pr-ui

一句话：**把界面减到几乎看不见，让内容成为屏幕上唯一的主角。**

**适用于任何界面，不依附于任何单一形态。** 对话页只是第一个落地场景；列表、表格、表单、文档、看板用的是同一套规矩，区别在各自的解剖结构（见第六节与 `references/surfaces.md`）。

这套规范不是审美偏好，是三个可测量的事实推出来的：

| 事实 | 推论 |
| --- | --- |
| 屏幕上面积最大的色块，必然是最先被看到的东西 | 最大的色块必须是内容；一旦是容器（气泡、卡片、按钮），容器就成了主角 |
| 颜色一旦被用作装饰，就失去了表意能力 | 整屏只留一个彩色，且只表状态 |
| 人眼把"层级"读作对比度差，而对比度差可以只来自字号和留白 | 底座压到几乎无色，层级不靠底色深浅 |

数值来源与出处见 `references/design-tokens.md`（ryugi 实测）与 `references/pr-agent-case.md`（一个完整落地案例）。

## 三条硬规矩

先记这三条，下面全部是它们的推论。

1. **整屏只有一个彩色，且只用来表示状态**（在线点、已完成、失败）。不用来表示按钮、不用来表示焦点、不用来描边卡片。
2. **层级只靠留白、字号、1px 线来拉。** 不靠底色深浅，不靠阴影大小。
3. **面积最大的色块必须是内容本身。** 如果最大的一块颜色是"容器"（气泡、卡片、按钮、表头灰底），说明容器抢了主角。

## 先定世界观（在三条规矩之前）

三条规矩管"长什么样"，但它们管不了"这东西凭什么在这里"。判据不是好看，也不是真实，而是**和谐**——而和谐可以拆成一张问题表：

| 每个界面都会遇到 | 你要回答的 |
| --- | --- |
| 读者从哪进来、第一眼看到什么 | |
| 他正在做什么事 | |
| 状态变化怎么表达 | |
| 等的时候是什么样 | |
| 什么都没有时说什么 | |
| 出错了怎么说话 | |
| **什么不能出现** | |

**答不出来的东西，放上去就是"贴上去的"。** 最后一行跟前六行一样重要：世界不只告诉你做什么，也告诉你不能做什么，这是减法的第一步。

填表方法、一个填好的示范、以及"为什么加连续打卡不对但加可勾选条目对"的推理，见 `references/worldview.md`。
参考别人的界面时**只取规则不取像素**——从 ryugi 那页拿的是"描边 + 极淡双层影"这条公式，不是它的便签和跳格子的小人。

## 一、底座

底座的目标是"像纸"——有质感但无色相。核心配方是三层：

```css
/* 1. 画布:极浅灰 + 点阵,提供"可摊开的桌面"的质感。纯页面可省,看板/自由布局必须有 */
background: #f4f4f5 radial-gradient(#d4d4d8 1px, transparent 1px) 0 0 / 16px 16px;

/* 2. 面:纯白,靠"描边 + 极淡投影"立起来,不靠阴影浓度的渐变 */
background: #fff;
box-shadow: 0 0 0 1px #e0e0e3, 0 2px 5px rgba(0, 0, 0, .14);

/* 3. 焦点:把描边压深一格,而不是发光 */
border-color: #6b6b72;   /* 不是 box-shadow: 0 0 0 3px rgba(accent,.18) */
```

关键在 **`0 0 0 1px` 描边 + 极小偏移的柔影**这两层。单层重阴影立刻廉价；`0 4px 20px rgba(0,0,0,.1)` 那种"悬浮卡片"是现代设计里最烂大街的一招。

完整 token 表（亮色 + 暗色、含透明度与安全区）见 `references/design-tokens.md`。
可直接落地的 CSS 见 `templates/pr-ui.css`（`.pr-ui` 作用域，无依赖，复制即用）。

**暗色不是第二套皮肤，是同一组变量换值。** 不要写 `.dark .card {}` 这种第二条样式链，只换 `--pr-*` 的值。

## 二、层级：字号、行高、留白

**字号是相对的，基准是 14。** 应用页的正文就是 14；阅读页可以到 15–16，因为那里没有控件跟它抢注意力。

| 层级 | 字号 | 行高 | 字重 | 颜色 |
| --- | --- | --- | --- | --- |
| 页面标题 | 20–22 | 1.3 | 500 | `--pr-text` |
| 区块标题 / 顶栏标题 | 14 | 1.4 | 500 | `--pr-text` |
| 正文 | 14（窄屏可 13.5） | 1.7–1.78 | 400 | `--pr-text` |
| 次级文字（说明、行内第二层） | 13.5 | 1.6 | 400 | `--pr-text-2` |
| 标签（字段名、组标题、表头） | 11 | 1.4 | 600 | `--pr-text-2` |
| 元信息（时间、来源、计数） | 11 | 1.5 | 400 | `--pr-muted` |
| 数字 / KPI | 28–32 | 1.1 | 500 | `--pr-text` |

四条容易漏的：

- **正文比你以为的小一格**：15px 在手机上是"标题感"，14px 才读得舒服。字号小一档、行高松一档，结果是同屏更多但更从容。
- **层级差不靠"再加一个灰"**：全套只有三档灰（100% / 72% / 60% 墨）。想再分一层时，先试试加留白，别加颜色。
- **所有数字加 `font-variant-numeric: tabular-nums`**。时长、计数、金额、比率会跳动，非等宽会让整行左右抖——这是最容易被察觉又最说不清"哪里不对劲"的细节。
- **间距按 4 的倍数**，组内 8–12、组间 24–32、区块间 48–64。间距对比拉开了，层级自然出来，一个线框都不用画。

## 三、颜色：先定角色，再挑颜色

只有四个角色，每个角色只有一个意思：

| 角色 | 干什么 | 约束 |
| --- | --- | --- |
| 纸 | 所有东西画在这上面 | 1 个 |
| 墨 | 字、线、图标 | **1 种颜色**，用 alpha 分层 |
| 讯号 | 只代表"这个状态成立" | 1 个，全站唯一有颜色的东西 |
| 警示 | 只在出错时出现 | 1 个，必须和讯号色差得够远 |

墨**只有一种颜色**，层级靠 alpha 分层，而且每一层都要量过对比度——实测下来 11px 小字在亮色底上 alpha 低于 60%（4.94:1）就不合格，浅灰 + 小字是双重惩罚。
分档表与实测值见 `references/design-tokens.md` D 节（pr-agent 存量的 `--pr-muted` 就是 2.50:1 的反例）。

**给预设，不给旋钮。** 开放任意色码等于让人随手拆掉其中一块，而他没有工具去量——所以模板只提供调好的预设，能填的只有内容。

## 四、动效

**只做两件，其余全部不做。**

**1）入场：轻微位移，不叠 scale。**
```css
.pr-ui .pr-enter { animation: prIn .5s cubic-bezier(.34, 1.56, .64, 1) both; }
@keyframes prIn { from { opacity: 0; transform: translateY(8px); } to { opacity: 1; transform: none; } }
```
弹簧曲线 `cubic-bezier(.34,1.56,.64,1)`（有轻微过冲）负责"活"，位移负责"从哪来"。**不要同时 scale**——长列表里每条都缩放弹跳会很吵。

**2）静止：极轻的呼吸**，只给"活着的东西"（在线点、进行中状态、头像），不给静态元素。

**必须有的降级：**
```css
@media (prefers-reduced-motion: reduce) {
  .pr-ui *, .pr-ui *::before, .pr-ui *::after {
    animation-duration: .01ms !important;
    transition-duration: .01ms !important;
  }
}
```

**两条曲线分工，别混用**：`--pr-spring` 给"有质量的东西"（按压、入场、勾选圈）；`--pr-ease`（expo-out）给"图层出现"（抽屉、弹层、位移）。弹层用 spring 会显得在抖。

**带物理的动效只在"物体移动"时用**（小人跳过去、抽屉拉开），做法是 squash & stretch：起跳前压扁 `scale(1.14,.82)` → 腾空拉长 `scale(.94,1.08)` → 落地再压扁 `scale(1.16,.8)` → 回弹 `scale(.98,1.03)`。标准动画十二原则。关键帧与时序见 `references/motion.md`。

**禁止：** `transition: all .3s ease`。它意味着你没想过哪个属性该动、动多久。

## 五、结构：把"决定"从散文里拎出来

这是这套规范里唯一改产品、不只是改外观的一条，也是收益最大的一条。**不限形态**：对话里的建议、文档里的步骤、表单里的选项、设置里的一组开关，都适用。

**识别信号**：一段文字里出现"接下来可以这样：A；B；C"——读者得在脑子里自己拆。
**做法**：拆成一行一个控件，必要时底部给一行计数或一个收束动作。

```
○ 今天剩下的跑量换成快走
● 泡沫轴滚髂胫束，每侧 2 分钟      ← 已完成,整行转 muted
○ 跑前加一组臀中肌激活
3 条 · 已完成 1 条
```

四条通用要求：

- **一项一个控件**，不要"整段可点"。
- **状态要有形状差异**（空心→实心、有勾），不能只靠颜色。
- **状态要能持久**，且 key 用内容本身的稳定标识（文本哈希），不要用会变的记录 id。
- **单条不渲染成列表**，一个孤零零的勾选框很怪，退回普通段落。

在对话里落地成 GFM task list 的完整方案（解析规则、持久化、四个坑）见 `references/checklist-pattern.md`。

## 六、形态：不同页面怎么套同一套规矩

规矩不变，**变的是这个形态自己的解剖结构**。每个形态都有一件它必须做好的事：

| 形态 | 必须做好的事 | 一句话要点 |
| --- | --- | --- |
| 列表 / 信息流 | 扫视中定位 | 行的四段顺序固定，**用线不用卡片** |
| 表格 | 数字可比 | 去竖线、数字右对齐等宽、行高 34–38 |
| 详情 / 文档 | 让人读完 | 行宽 60–75 字符，标题上边距 > 下边距 |
| 表单 | 填错立刻能改 | 标签顶置、聚焦压描边、错误双信号 |
| 设置 | 找到并改对一个 | 分组不平铺，开关用正向措辞 |
| 空态 | 给下一步 | 一句话 + 一个动作，不给插画 |
| 加载 | 不让人焦虑 | <300ms 什么都不做；骨架屏形状要对 |
| 弹层 / 抽屉 | 不让人出不去 | 遮罩 32% 黑，进入用 expo 不用 spring |
| 导航 | 知道自己在哪 | 一级最多一层，当前项用字重不用底色 |
| 仪表盘 | 一屏回答一个问题 | 数字第一，图表不用彩色图例 |

每种形态的解剖结构、数值和**该形态特有的翻车方式**见 `references/surfaces.md`。

跨形态唯一不能变的是：**同一套 token、同一套字阶、同一个圆角梯子。** 这就是"笔触缝"的来源。

## 七、改造流程（对着现有项目）

按顺序做，前两步决定 80% 的观感。

1. **数彩色**：截图，圈出所有非灰度像素。超过 1 处状态色 + 1 处品牌色就是多了。
2. **找面积最大的色块**：如果是容器（卡片/气泡/按钮/表头底），先解决它，别管圆角和阴影。
3. **量字号**：正文 > 14px 就降一档，行高 < 1.6 就加一档。数字加 tabular-nums。
4. **查焦点态**：有没有发光？有就改成描边压深一格。
5. **查动效**：grep `transition: all`，全部改成具体属性。
6. **做黑白测试**：把颜色全降成灰，两个状态还分得出来吗？分不出来说明形状没做好，颜色不该是唯一信号。
7. **查接缝**：见下一节。
8. **截图验证**：真实组件跑起来拍，不要凭感觉。方法见 `references/visual-qa.md`。

## 八、接缝：静态对了之后，检查动态

反模式清单管静态——一个东西单独看长什么样。真正让人觉得"像拼起来的"的，是**接缝**：两个东西交接的那一瞬没接好。这种感觉通常是"说不出来但怪怪的"，拆开只有五种：

| 缝 | 没接好的样子 | 怎么检查 |
| --- | --- | --- |
| 时间 | 突然出现/消失，亮度像断电一样断掉 | 录屏逐格看那几帧 |
| 顺序 | 该先发生的晚了一步 | 把动作按时间写成一行一行 |
| 空间 | 跟旁边原本就在的东西对不上 | 叠在一起看层级、对齐 |
| 道理 | 用了不属于它的规则 | 问：**这条规则是谁的？** |
| 笔触 | 质感跟全站不是同一支笔 | 跟最典型的元件并排看 |

再加一个比上面五个都灵的问题：**它的下一步是什么？** 只有"现在"、没有前因后果的东西，看久了就会假。

逐条落到真实实例（勾选圈在弹但文字瞬时变色、圆角梯子四档太密、全部做完后没有收束）见 `references/seams.md`。
最后一条通常是**产品缺口**，调像素解决不了。

## 反模式清单（见到就改）

| 反模式 | 为什么错 | 改成 |
| --- | --- | --- |
| 焦点发光 `0 0 0 3px rgba(accent,.18)` | 彩色被用作装饰，且发光是"廉价 Web2.0"的强信号 | `border-color` 压深一格 |
| 彩色主按钮 / 彩色 CTA | 视觉重量压在"操作"上，内容被压下去 | 深色实心，把彩色留给状态 |
| 每个条目都套卡片（含每条消息一个气泡） | 卡片是屏幕上最大的色块，成了主角；一屏还只能装五条 | 裸内容 + 1px 线分隔，卡片只给"独立可整体操作的东西" |
| 单层重阴影 `0 4px 20px rgba(0,0,0,.1)` | 悬浮感廉价 | `0 0 0 1px 线 + 0 2px 5px 柔影` |
| 表格四件套：全边框 + 表头灰底 + 斑马纹 + 数字居中 | 就是标准后台模板 | 去竖线、数字右对齐等宽、行高分隔 |
| `transition: all .3s ease` | 没想过动什么 | 指名属性 + spring/expo 曲线 |
| 手挑"品牌色 + 白字/黑字" | 20 个颜色必然有几组糊 | 算 WCAG 相对亮度：`L > 0.4` 用黑字，否则白字 |
| 暗色写第二套类名 | 两套样式必然漂移 | 同变量换值 |
| 正文 15–16px + 行高 1.5 | 像标题、像后台 | 14px / 1.78 |
| 11px 小字配浅灰 | 小字 + 浅灰是双重惩罚，亮色底上 2.5:1 基本读不清 | 小字至少 60% 墨（4.94:1） |
| 两个状态只靠颜色区分 | 灰度、色盲、打印全崩 | 形状先区分，颜色只是第四重信号 |
| 空态插画 / "暂无数据" | 描述数据库，不跟人说话 | 一句话 + 一个动作 |
| 图表彩色图例 | 图例色是装饰色，违反硬规矩一 | 一条墨色 + 一条强调色 |

## 案例

`references/pr-agent-case.md` 是一次完整的改版对照（对话页：去掉 AI 气泡、把建议拎成可勾选条目、输入区从胶囊降成纸条），含逐文件 before/after 与回滚方式。
**它是案例，不是规范**——照抄它的像素（气泡、勾选圈、composer 的 14px 圆角）搬到别的形态上就是"贴上去的"。可迁移的只有它为什么这么做。
