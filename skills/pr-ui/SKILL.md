# pr-ui

一句话：**把界面减到几乎看不见，让内容成为屏幕上唯一的主角。**

这套规范不是审美偏好，是三个可测量的事实推出来的：

| 事实 | 推论 |
| --- | --- |
| 屏幕上面积最大的色块，必然是最先被看到的东西 | AI 回复不要套气泡（气泡会变成主角） |
| 颜色一旦被用作装饰，就失去了表意能力 | 整屏只留一个彩色，且只表状态 |
| 人眼把"层级"读作对比度差，而对比度差可以只来自字号和留白 | 底座压到几乎无色，层级不靠底色深浅 |

数值来源与出处见 `references/design-tokens.md`（ryugi 实测）与 `references/pr-agent-case.md`（落地对照）。

## 三条硬规矩

先记这三条，下面全部是它们的推论。

1. **整屏只有一个彩色，且只用来表示状态**（在线点、已勾选、失败）。不用来表示按钮、不用来表示焦点、不用来描边卡片。
2. **层级只靠留白、字号、1px 线来拉。** 不靠底色深浅，不靠阴影大小。
3. **面积最大的色块必须是内容本身。** 如果最大的一块颜色是"容器"（气泡、卡片、按钮），说明容器抢了主角。

## 先定世界观（在三条规矩之前）

三条规矩管"长什么样"，但它们管不了"这东西凭什么在这里"。判据不是好看，也不是真实，而是**和谐**——而和谐可以拆成一张问题表：

| 每个界面都会遇到 | 你要回答的 |
| --- | --- |
| 读者从哪进来、第一眼看到什么 | |
| 他正在做什么事 | |
| 状态变化怎么表达 | |
| 等的时候是什么样 | |
| 什么都没有时说什么 | |
| 出错了怎么说话 | |
| **什么不能出现** | |

**答不出来的东西，放上去就是"贴上去的"。** 最后一行跟前六行一样重要：世界不只告诉你做什么，也告诉你不能做什么，这是减法的第一步。

填表的完整方法、pr-agent 填好的示范、以及"为什么加连续打卡不对但加可勾选条目对"的推理，见 `references/worldview.md`。
参考别人的界面时只取规则不取像素——从 ryugi 那页拿的是"描边 + 极淡双层影"这条公式，不是它的便签和跳格子的小人。

## 一、底座

底座的目标是"像纸"——有质感但无色相。核心配方是三层：

```css
/* 1. 画布:极浅灰 + 点阵,提供"可摊开的桌面"的质感 */
background: #f4f4f5 radial-gradient(#d4d4d8 1px, transparent 1px) 0 0 / 16px 16px;

/* 2. 卡片/板:纯白,靠"描边 + 极淡投影"立起来,不靠阴影浓度的渐变 */
background: #fff;
box-shadow: 0 0 0 1px #e0e0e3, 0 2px 5px rgba(0, 0, 0, .14);

/* 3. 焦点:把描边压深一格,而不是发光 */
border-color: #6b6b72;   /* 不是 box-shadow: 0 0 0 3px rgba(accent,.18) */
```

关键在 **`0 0 0 1px` 描边 + 极小偏移的柔影**这两层。单层重阴影立刻廉价；`0 4px 20px rgba(0,0,0,.1)` 那种"悬浮卡片"是现代设计里最烂大街的一招。

完整 token 表（亮色 + 暗色、含透明度与安全区）见 `references/design-tokens.md`。
可直接落地的 CSS 见 `templates/pr-ui.css`（`.pr-ui` 作用域，无依赖，复制即用）。

**暗色不是第二套皮肤，是同一组变量换值。** 不要写 `.dark .card {}` 这种第二条样式链，只换 `--pr-*` 的值。

**颜色先定角色，再挑颜色。** 只有四个角色：纸、墨、讯号、警示，每个角色只有一个意思。
墨**只有一种颜色**，层级靠 alpha 分层，而且每一层都要量过对比度——实测下来 11px 小字在亮色底上 alpha 低于 60%（4.94:1）就不合格，浅灰 + 小字是双重惩罚。
（pr-agent 现在的 `--pr-muted` 是 2.50:1，读不清，属于该改的存量问题。分档表见 `references/design-tokens.md` D 节。）


## 二、排版

| 用途 | 字号 | 行高 | 字重 | 颜色 |
| --- | --- | --- | --- | --- |
| 正文 | 14px（窄屏可用 13.5） | 1.7–1.78 | 400 | `--pr-text` |
| 用户自己说的话 | 13.5px | 1.6 | 400 | `--pr-text`，底色 `--pr-user-card` |
| 标题（顶栏） | 14px | — | 500 | `--pr-text` |
| 元信息（时间/来源/计数） | 11px | 1.5 | 400 | `--pr-muted` |
| 标签 | 11px | — | 600 | `--pr-text-2` |
| 条目标题（可选项） | 13.5px | 1.6 | 400 | 勾选后 `--pr-muted` |

两条容易漏的：

- **正文比你以为的小一格**：15px 在手机上是"标题感"，14px 才读得舒服。字号小一档、行高松一档，结果是同屏更多但更从容。
- **所有数字加 `font-variant-numeric: tabular-nums`**。时长、计数、配速会跳动，非等宽会让整行左右抖——这是最容易被察觉又最说不清"哪里不对劲"的细节。

## 三、动效

**只做两件，其余全部不做。**

**1）入场：轻微位移，不叠 scale。**
```css
.pr-ui .msg { animation: prIn .5s cubic-bezier(.34, 1.56, .64, 1) both; }
@keyframes prIn { from { opacity: 0; transform: translateY(8px); } to { opacity: 1; transform: none; } }
```
弹簧曲线 `cubic-bezier(.34,1.56,.64,1)`（有轻微过冲）负责"活"，位移负责"从哪来"。**不要同时 scale**——长列表里每条都缩放弹跳会很吵。

**2）静止：极轻的呼吸**，只给"活着的东西"（在线点、进度、头像），不给静态元素。
```css
@keyframes prBreath { 0%,100% { transform: scale(1); } 50% { transform: scale(1.05); } }
```

**必须有的降级：**
```css
@media (prefers-reduced-motion: reduce) {
  .pr-ui *, .backdrop { animation-duration: .01ms !important; transition-duration: .01ms !important; }
}
```

**带物理的动效只在"物体移动"时用**（小人跳过去、抽屉拉开），做法是 squash & stretch：起跳前压扁 `scale(1.14,.82)` → 腾空拉长 `scale(.94,1.08)` → 落地再压扁 `scale(1.16,.8)` → 回弹 `scale(.98,1.03)`。标准动画十二原则。实测关键帧与时序见 `references/motion.md`。

**禁止：** `transition: all .3s ease`。它意味着你没想过哪个属性该动、动多久。

## 四、结构：把"决定"从正文里拎出来

这是这套规范里唯一改产品、不只是改外观的一条，也是收益最大的一条。

**识别信号**：正文里出现"接下来三天可以这样：A；B；C"——用户在脑子里得自己拆。
**做法**：拆成可点条目，每行一个控件，底部一行计数。

```
○ 今天剩下的跑量换成快走
● 泡沫轴滚髂胫束，每侧 2 分钟      ← 已勾,整行转 muted
○ 跑前加一组臀中肌激活
3 条建议 · 已勾 1 条
```

实现要点（踩过的坑，务必看 `references/checklist-pattern.md`）：

- **勾选状态挂条目文本的哈希，不挂消息 id。** 消息 id 在"本地临时 id → 服务端 id → 历史重拉"过程中会变，挂 id 上的勾会凭空消失。
- **单条不渲染成清单。** 只有一条时退回普通 markdown，一个孤零零的勾选框很怪。
- **代码块里的 `- [ ]` 不解析**（``` 围栏内跳过）。
- **数据契约最省事的一版：让模型输出 GFM task list（`- [ ]`），前端渲染。** 零后端改动。
- **改 prompt 前先确认原 prompt 没禁止分点**——禁分点的 prompt 会让清单永远等不到。

## 五、改造流程（对着现有项目）

按顺序做，前两步决定 80% 的观感。

1. **数彩色**：截图，圈出所有非灰度像素。超过 1 处状态色 + 1 处品牌色就是多了。
2. **找面积最大的色块**：如果是容器（气泡/卡片/按钮），先解决它，别管圆角和阴影。
3. **量字号**：正文 > 14px 就降一档，行高 < 1.6 就加一档。数字加 tabular-nums。
4. **查焦点态**：有没有发光？有就改成描边压深一格。
5. **查动效**：grep `transition: all`，全部改成具体属性。
6. **做黑白测试**：把颜色全降成灰，两个状态还分得出来吗？分不出来说明形状没做好，绿色不该是唯一信号。
7. **查接缝**：见下一节。
8. **截图验证**：真实组件跑起来拍，不要凭感觉。方法见 `references/visual-qa.md`。

## 六、接缝：静态对了之后，检查动态

反模式清单管静态——一个东西单独看长什么样。真正让人觉得"像拼起来的"的，是**接缝**：两个东西交接的那一瞬没接好。这种感觉通常是"说不出来但怪怪的"，拆开只有五种：

| 缝 | 没接好的样子 | 怎么检查 |
| --- | --- | --- |
| 时间 | 突然出现/消失，亮度像断电一样断掉 | 录屏逐格看那几帧 |
| 顺序 | 该先发生的晚了一步 | 把动作按时间写成一行一行 |
| 空间 | 跟旁边原本就在的东西对不上 | 叠在一起看层级、对齐 |
| 道理 | 用了不属于它的规则 | 问：**这条规则是谁的？** |
| 笔触 | 质感跟全站不是同一支笔 | 跟最典型的元件并排看 |

再加一个比上面五个都灵的问题：**它的下一步是什么？** 只有"现在"、没有前因后果的东西，看久了就会假。

逐条落到 pr-agent 的实例（勾选圈在弹但文字瞬时变色、圆角梯子四档太密、勾完全部后没有收束）见 `references/seams.md`。
最后一条通常是**产品缺口**，调像素解决不了。

## 反模式清单（见到就改）

| 反模式 | 为什么错 | 改成 |
| --- | --- | --- |
| `box-shadow: 0 0 0 3px rgba(accent,.18)` 焦点发光 | 彩色被用作装饰，且发光是"廉价 Web2.0"的强信号 | `border-color` 压深一格 |
| 彩色发送按钮/彩色主 CTA | 视觉重量压在"操作"上，内容被压下去 | 黑色或深色实心，把彩色留给状态 |
| 每条消息都套气泡 | 气泡是屏幕上最大的色块，抢主角 | AI 回复裸文本 + 一行 11px 元信息 |
| 单层重阴影 `0 4px 20px rgba(0,0,0,.1)` | 悬浮感廉价 | `0 0 0 1px 线 + 0 2px 5px 柔影` |
| `transition: all .3s ease` | 没想过动什么 | 指名属性 + spring/expo 曲线 |
| 手挑"品牌色 + 白字/黑字" | 20 个颜色必然有几组糊 | 算 WCAG 相对亮度：`L > 0.4` 用黑字，否则白字 |
| 暗色写第二套类名 | 两套样式必然漂移 | 同变量换值 |
| 正文 15–16px + 行高 1.5 | 像标题、像后台 | 14px / 1.78 |
| 11px 小字配浅灰 | 小字 + 浅灰是双重惩罚，亮色底上 2.5:1 基本读不清 | 小字至少 60% 墨（4.94:1） |
| 两个状态只靠颜色区分 | 灰度、色盲、打印全崩 | 形状先区分，颜色只是第四重信号 |
